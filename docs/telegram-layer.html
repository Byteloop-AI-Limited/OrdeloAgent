Rules that hold everywhere

  • The webhook route has no business logic and always answers 200 after the secret check (Telegram retries anything else).
  • Each bot has its own aiogram Dispatcher and router tree. Routers are built fresh per bot, never shared.
  • Consequential handlers opt into the inbox: restaurant order/kitchen buttons, invite Yes, verified rider contact, signup choices, offer and job-card buttons, and rider text on an active Telegram thread. Read-only, fallback, scratchpad and unmatched updates make no inbox calls. For background agent work, done means queued.
  • The app never calls set_webhook or delete_webhook. That is notebook cell 4.
  • One webhook per bot token: a token shared with another service sends every update to the last URL set.
  • Missing or malformed tgram_rest_admin_bot_token / _webhook_secret stops the service at import.

The pattern

The RPC owns the logic. One Python wrapper per domain. Both files name each other.

  1. Table(s) and their RPCs live in one feature file (telegram/t_invites.sql), never under migrations/.
  2. The RPC is atomic and returns jsonb with a result string (ok, expired, revoked ...).
  3. The Python wrapper (invites.py) is a typed async def per RPC: asyncio.to_thread, service-role client, a small outcome dataclass.
  4. Handlers call the wrapper only; they never query the table or re-implement the rule.
