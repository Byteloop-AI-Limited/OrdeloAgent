R1a: what changed in the Ordelo service, and why

1 October 2026, branch release/ordelo-agg, uncommitted and not deployed. R1a lays the payment and order groundwork that the R2 payment-path check needs. Every new behaviour is behind an ordelo_config flag that is off when the key is missing, so WhatsApp orders behave exactly as today until you switch something on.

1. How payment-complete now works plan M2, ADR-0003, ADR-0004

The test route /payment-hooks/payment-complete-test/{order_id} now returns 404 unless ENABLE_PAYMENT_TEST_ROUTES is on. When on, it goes through the same once-only path.

The safety alert: a SQL job finds paid orders with no delivery or takeaway summary after 2 minutes and posts them to /payment-hooks/init-reconciler, which tells overwatch once per order. It alerts only; it changes nothing.

4. Switching it on one step at a time; each step undoes on its own

  1. Run the SQL file.
  2. Deploy the code. With no flags set, it behaves as today.
  3. On the test restaurant, turn on one flag, run a WhatsApp delivery, takeaway and pay-at-restaurant order, then the next flag.
  4. Same in production, outside service hours.
  5. Set PAYMENT_INIT_RECONCILER_SINCE and schedule the alert job.

6. What's next

  1. SELECT create_thread('WEB', NULL) for a web thread.
