R1: how the Ordelo foundation migration rolls out

R1 has two layers. The database layer is additive: new columns with defaults and new tables. The old code keeps working on top of it. The code layer ships switched off and is turned on one flag at a time, so WhatsApp customers, restaurants and riders see the same behaviour at every step.

6. Checks to run no backfill: there are no live orders

Before step 1 and before each flag flip in prod: no order mid-fulfilment. Expect no rows, apart from test or abandoned orders you recognise.

SELECT order_number FROM delivery_summary
 WHERE status NOT IN ('completed','timedout')
UNION ALL
SELECT order_number FROM takeaway_summary
 WHERE status NOT IN ('completed','declined')
UNION ALL
SELECT order_number FROM food_order
 WHERE payment_status = 'requires_payment'
   AND order_dt = CURRENT_DATE;

Any WhatsApp order the notifier sees without a subscription goes to its restaurant app anyway (the fallback). New WhatsApp orders get their subscription at creation.
